# web — app conventions

A **TanStack Start** SSR app (scaffolded/updated by the `prepare-tanstack-start-app` skill). This
file holds the **stack + structure conventions**. If you split out app-specific UI conventions (a
shared layout component, link defaults, …), keep those in `src/CLAUDE.md`.

## Stack

TanStack Start (SSR, file-based routing) + React 19 + Vite + Tailwind v4 + **shadcn/ui**. **No
Nitro** — `vite build` emits a Web `fetch` handler (`dist/server`) plus a static client
(`dist/client`). **srvx** (`server.ts`) runs that handler on Node and serves the assets. Deps stay
**real runtime imports** (not a self-contained bundle), so — unlike a bundled `.output/server` — a
new server-rendered dep needs **no `ssr.noExternal` entry**. Node ≥22.18 runs the `.ts` files
directly. Booted via plain `node server.ts` — **no tracer** (see Instrumentation below).

## Routes (`src/routes`)

File-based. `__root.tsx` is the root layout — **keep its `maximum-scale=1` viewport meta** (stops
iOS Safari auto-zooming into <16px inputs).

- **A route's page component is a named `function` in the route file**, referenced as
  `component: PageName` — not a separate `components/` file, and not an inline arrow. A **named**
  function is required because `react-hooks/rules-of-hooks` only treats a PascalCase-named function
  as a component; an anonymous arrow on the lowercase `component` prop makes every hook read as a
  violation. Keep the page + its route-local helpers together below the `Route` export.
- **`src/components/` is for shared/reusable UI only** — used by more than one route or composed
  inside pages (a shared shell, cross-route `errorComponent`/`notFoundComponent`). A component goes
  there because it's genuinely shared, *never* just because it's "the page for a route."
- **Nest into a folder only when a path segment actually branches** — multiple child leaves, or an
  index page *plus* subroutes. A single leaf stays a flat file (`restore.$tenant.tsx` →
  `/restore/$tenant`); dotted names map dots to slashes. A branching segment gets a segment-named
  layout file next to a same-named folder (`foo.tsx` + `foo/…`) — **no `route.tsx`**. `index.tsx`
  (or dotted `*.index.tsx`) is a segment's index.
- **Colocation with a leading `-`:** any file/dir starting with `-` is ignored by the router.
  `-server.ts` for a route(-group)'s server fns once there are **more than a couple** and/or they're
  **shared across several routes** (a lone route-specific fn stays inline; app-wide → `~/server`).
  `-components/` for one-route components; `-<name>/` for route-specific utils/hooks/types + tests.
- **Server / "API" routes** are ordinary route files with a `server: { handlers: { GET, POST } }`
  block instead of a `component`; `.ts` when there's no JSX. Return `Response.json(...)` (Web API) —
  **not** the deprecated `json` helper from `@tanstack/react-start`.
- After adding/removing/renaming a route, `src/routeTree.gen.ts` is regenerated by the
  `tanstackStart()` vite plugin — run `pnpm build` (or `dev`).

## Data loading

Route **`loader`s call the app's server functions** (`createServerFn`) so first-paint data is on the
page before it renders — no fetch-on-mount for the first render. Add client React Query only for
deliberately-live widgets.

## Imports — the `~/` alias

`~/*` → `src/*` (tsconfig `paths`, resolved at build by vite's `resolve: { tsconfigPaths: true }`).
Use `~/` for anything **cross-tree**; relative `./` only for **siblings** and colocated `-` files. No
`#/`, no `@/`.

## UI — shadcn/ui (wrap, don't edit)

Compose **shadcn primitives + Tailwind directly** (thin components); theme **centrally** via CSS
variables in `src/styles.css` — never fork a component to restyle it.

- **`src/components/ui/` is vendored shadcn CLI output — keep it pristine.** It's **excluded from
  ESLint** so `shadcn diff`/`--overwrite` updates stay clean. To change behavior, **wrap** the
  primitive in a new component under `src/components/ui-kit/` (or a feature folder) — don't edit the
  `ui/` file. (Sanctioned exception: adapting a generated wrapper that hard-codes an integration you
  don't use — e.g. `ui/sonner.tsx` drops the `next-themes` hook for a single-theme app.)
- `~/` is the CLI alias, wired in `components.json` (`aliases`), so `npx shadcn@latest add <name>`
  writes correct imports and installs the Radix deps. Update via `npx shadcn@latest diff` then
  `add <name> --overwrite`, reviewing the git diff. The shadcn CLI is fast-moving — confirm flags
  against `shadcn --help` / https://ui.shadcn.com. The `cn` helper is `~/lib/utils`.

## CSS Modules — the escape hatch

Almost all styling is **Tailwind utilities** on the primitives. A colocated **`*.module.css`** is the
escape hatch for the handful of things Tailwind can't express inline — chiefly **`@keyframes`** and
the rules that drive them — kept scoped to the one component that owns it instead of accreting in
`styles.css`. Name it after the component, use **camelCase** class names, import the map
(`import styles from './x.module.css'`; Vite scopes + types it via `vite/client`), and combine with
Tailwind via `cn('text-xs', styles.pulse)`. **Theme tokens stay global** — reference them with
`var(--token)`, don't redefine palette values in a module. Dynamic values flow in as inline CSS
custom properties (`style={{ '--dur': \`${ms}ms\` }}`) read by the module. Genuinely shared
cross-component CSS belongs in `styles.css`, not a module.

## Client entry & StrictMode (`src/client.tsx`)

A custom client entry replaces TanStack Start's default (which wraps the app in `<React.StrictMode>`).
This template omits StrictMode on purpose — its dev-only double-invocation is noise and breaks
single-shot effects. To opt back in, delete `src/client.tsx` or wrap `<StartClient/>` in `<StrictMode>`.

## Server functions & CSRF (`src/start.ts`)

Server fns (`createServerFn`) are same-origin RPC endpoints, so `createCsrfMiddleware` gates them
with a same-origin check (`Sec-Fetch-Site` → `Origin` → `Referer`). **Always keep it.** This
protection is opt-in in current TanStack Start: because this app defines a `createStart` instance,
Start does NOT auto-inject the default CSRF middleware — so without ours, server fns aren't
origin-checked at all and Start logs `server functions are not protected by the CSRF middleware`.
Scope it to `serverFn` (via `filter`) so router requests are untouched. Leave `origin` unset for the
normal same-origin case. Only set `origin` behind a reverse proxy that terminates TLS and strips
`Sec-Fetch-*` (e.g. a Cloudflare Tunnel), where the check falls back to comparing the browser's https
`Origin` against the internal http request URL → 403 on every server-fn POST (only writes fail; reads
run in the SSR loader).

## Surfacing server-fn errors (`src/start.ts` + `__root.tsx`)

A server-fn failure must never be swallowed. Two complementary, **additive** surfaces:

- **Mutations (POST):** a global **function middleware** in `src/start.ts` — its `.client()` phase
  wraps every server-fn call; on a rejection it toasts the message (`toast.error` from **sonner**,
  the shadcn toast, mounted once as `<Toaster/>` in `__root.tsx`) and **re-throws**. One unavoidable
  place → a swallowed mutation error is impossible by default and new server fns are covered
  automatically. Server-thrown `Error` messages serialize across the wire, so the toast has the real
  cause.
- **Reads (GET, in loaders) + render errors:** the root **`errorComponent`** in `__root.tsx`.

Because the middleware re-throws, existing call-site handling still runs — so **don't hand-wire a
per-call error banner** in new code; let the global surfaces do it.

## Production server (`server.ts`, srvx)

srvx runs the built `fetch` handler and serves `dist/client`. The `@ts-expect-error` on
`import handler from './dist/server/server.js'` is expected — a build artifact with no types.

## Instrumentation — deliberately omitted

This app ships **no tracer** (a documented deviation from the source `prepare-tanstack-start-app`
skill, which offers OpenTelemetry or Datadog). Both assume a collector to export to; this is a
single-user app on the owner's machine with no collector and no operator to page. Do not copy
`instrumentation.otel.ts` or add `@opentelemetry/*`/`dd-trace` packages. Add instrumentation if this
is ever deployed somewhere real.

## Build / deploy — no Dockerfile

There is **deliberately no `Dockerfile`**, matching `projects/tx-payees` ("No Dockerfile is
scaffolded by default; add one if the service is deployed standalone"). The skill's template
Dockerfile was scaffolded and then removed: it `COPY`s a package-local `pnpm-lock.yaml` that doesn't
exist in this monorepo (only the root lockfile does), and `@bank-bots/db` is a `workspace:*`
**TypeScript-source** dependency, so a working image needs a monorepo-aware build (`pnpm deploy` or
a filtered install from the repo root). Nothing here was ever deployed, so that was an unbuildable
artifact nobody would notice was broken.

Run it locally:

```bash
pnpm devtooie                       # whole workspace
pnpm devtooie cmd -p web -c dev     # just this app
pnpm -C projects/web run dev        # without devtooie (needs DATABASE_URL in env)
```
